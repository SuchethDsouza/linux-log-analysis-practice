Level: Beginner
Role: L1 Application / Production Support Engineer

Scenario:
You are working as an L1 support engineer. A team member gives you app.log and asks you to investigate a few basic issues using Linux commands.

Important:
Try to solve the problems yourself using grep, awk, sed, sort, uniq, cut, head and tail.
Do not look for solutions online.
When you are finished, send me your commands and I will review them.

TASK 12 - Real support question
A user reports:
"Payment failed for my account around 09:43."

Use the log to answer:
1. Which user had the payment failure around 09:43?
suchethdza@Ubuntu:~/Level1$ awk '/action=payment/ && /status=FAILED/ && $2 >= "09:43:00" && $2 <= "09:43:59" {print $5}' app.log
user=rahul ?


2. What was the exact time?
suchethdza@Ubuntu:~/Level1$ awk '/action=payment/ && /status=FAILED/ && $2 >= "09:43:00" && $2 <= "09:43:59" {print $5,$2}' app.log
user=rahul 09:43:29


3. Did a successful payment occur for that user afterward?
suchethdza@Ubuntu:~/Level1$ awk '/action=payment/ && /status=FAILED/ && $2 >= "09:43:00" && $2 <= "09:43:59" {print $5,$2,$7}' app.log
user=rahul 09:43:29 status=FAILED


The log actually shows:

09:43:29 ERROR app user=rahul action=payment status=FAILED
09:44:46 INFO  app user=rahul action=payment status=200

So:
Yes, Rahul's payment succeeded afterward.

This is a very important real-world troubleshooting lesson.

You cannot answer:
"Did it succeed afterward?"

by looking only at the failed entry.
You must search later entries for the same user and same action.
This is exactly the kind of thinking you'll need in production support.

RULES
1. Use the terminal.
2. Prefer Linux commands instead of manually reading every line.
3. Start with simple commands.
4. You may combine commands using | (pipe).
5. Do not change app.log directly.
